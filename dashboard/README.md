# Dashboard

Next.js 16 (App Router) with `@supabase/ssr`. It signs owners in with a magic link and shows the fleet live: bots, state, versions, commands and events. It queues `ping` and `status`. Plan: [docs/plan.md](../docs/plan.md), Phase 1 workstream 6.

| Path | Contents |
|---|---|
| `proxy.ts`, `lib/supabase/proxy.ts` | Refreshes the session on every request with `getClaims()`, and sends signed-out visitors to `/login` |
| `lib/supabase/server.ts`, `client.ts` | Supabase clients for server code (cookies through `getAll`/`setAll`) and for the browser (realtime) |
| `app/login`, `app/auth/confirm`, `app/auth/signout` | Magic-link sign-in (`signInWithOtp`, then `verifyOtp` on `/auth/confirm`) and sign-out |
| `app/fleet` | Server-rendered table, then realtime updates on `bots` and `bot_state`. A version-drift badge marks bots whose bus or ArchHUD version differs from what most of the fleet runs |
| `app/bots/[id]` | One bot: state, the last 50 commands and events |
| `app/commands` | Queues `ping` or `status`. The hub assigns the epoch and cseq; row level security allows only the bot's owner |
| `lib/protocol.ts` | Generated by `packages/protocol/codegen.py`. Do not edit |

Only the publishable key is used; row level security (`supabase/migrations/0002_rls.sql`) decides what each owner sees.

## Setup

1. Copy `.env.example` to `.env.local` and fill in the project URL and publishable key.
2. In Supabase Auth:
   - add the dashboard URL to the redirect URLs;
   - change the magic link email template to link to
     `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email&next=/fleet`.
3. Owners and device users are created in Supabase Auth. `signInWithOtp` is called with `shouldCreateUser: false`, so strangers cannot sign themselves up.

## Checks

```sh
npm ci
npm run lint && npm run typecheck && npm test      # eslint, tsc, node --test on lib/
npm run build                                      # NEXT_PUBLIC_* values are baked in at build time
npm run e2e                                        # Playwright smoke tests on the build
```

The smoke tests need no Supabase project. They build against an unreachable URL and check the signed-out paths:
- redirects to `/login`;
- a broken sign-in link;
- a hub that cannot be reached.

To use an already installed Chromium, set `PW_CHROMIUM_PATH`. The plan's realtime test waits for a live project: insert a `bot_state` row and watch the fleet table update.
